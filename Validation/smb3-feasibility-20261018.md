# SMB3 接入可行性评估（2026-10-18）

## 结论

技术上可以接入，建议目标锁定为 **NES/FC 美版 Super Mario Bros. 3（PRG1）**。当前工程适合复用菜单、输入、手柄、设置、音频接口、像素渲染、AABB 基础碰撞和编辑器框架；SMB3 的玩家规则、世界地图、关卡连接、道具库存、镜头和对象系统应作为独立作品实现。

如果只做一个“能打开、能跑几关”的展示版，约 10–15 个工作日；如果做用户前面要求的原生可编辑、高还原、包含世界地图和完整主线的版本，按单人全职约 **56–108 个工作日（8–14 周）**，再加逐关人工校准时间。兼职开发约 3–5 个月更现实。

## 本次核对的参考规模

已读取 `captainsouthbird/smb3` 的 disassembly，固定提交 `09b1bd81a788de8ceec664a34094e84ddb463117`，只作为研究和规模核对，没有导入 Unity。

- 727 个汇编/包含文件，约 101,943 行汇编代码。
- 264 个对象布局文件，372 个关卡定义汇编文件，58 个世界地图/地图数据汇编文件。
- `game.xml` 定义约 197 类对象、594 个对象贴图组合；CHR 目录有 128 张 PCX 图。
- 对象布局中能看到飞船、坦克、堡垒、世界地图敌人、管道、云平台、斜坡相关对象，以及 Boom Boom、Koopaling、尾巴/狸猫/青蛙/锤子等 SMB3 专属内容。
- 该仓库没有发现独立 LICENSE 文件；README 说明它用于研究和 ROM hack。Nintendo 原始程序、图形、音乐仍有版权，不能把仓库或原 ROM 内容直接当成可自由发布的游戏素材。

## 当前工程的硬限制

- `MarioGame.Initialize` 目前要求 `Levels.Length == 64`。
- `MarioMenuNavigation` 的选关页固定为 8 个世界 × 4 关，并只处理初代、日版二代、猫里奥三个作品。
- `LevelData` 通过 `J-` 前缀和固定位置解析世界/关卡号；通关关系目前按 `Stage == 4` 和 8-4 结局处理。
- 当前 `ClassicMotor`、敌人和碰撞规则主要面向 SMB1；直接复用会得到换皮版，不能得到 SMB3 手感。
- 当前编辑器也固定在初代/日版二代的 64 关结构，需要改成按作品配置生成关卡列表、世界地图节点和区域入口。

## 需要新增的系统

1. **作品与流程层**：SMB3 作品配置、世界地图、关卡节点/分支、锤子和笛子等库存、通关后的地图状态、飞船移动和回退规则。
2. **玩家控制器**：跑步蓄力表、狸猫叶子飞行/尾巴攻击、Tanooki 石像、青蛙套装、锤子套装、持物和投掷、斜坡、垂直关卡、自动卷屏，以及 SMB3 独立受伤和变身规则。
3. **对象与敌人**：Boom Boom、各世界 Koopaling、Boomerang Bro、Dry Bones、Boo、Nipper、Ptooie、火焰蛇、Boss Bass、带小怪的敌人、旋转火棒/旋转盘、流沙、风、水流、飞船/坦克机关等。参考 XML 已列出约 197 类对象，不能只映射当前已有敌人名称。
4. **数据导入**：将 SMB3 的图块/对象布局格式转换成 Unity 可编辑 `LevelData` 或新的 SMB3 数据资产；需要处理同一关的内区、奖励区、管道和出口。
5. **画面与音频**：SMB3 的图块、调色板、动画、HUD、世界地图和音乐规格独立于当前 256×240 初代素材。应建立 `SMB3/` 资源目录和作品专用渲染配置。
6. **验证**：先做可重复输入轨迹，再按每个世界地图节点、每个关卡、每种变身和每种特殊对象验收。当前 64 关压力测试不能证明 SMB3 正确。

## 建议方案

先做 **世界 1 地图 + 1-1 + 蘑菇/火花/叶子 + 持壳/基础斜坡 + 一个堡垒/Boom Boom 样例**。这个纵向样例能在 10–15 个工作日内验证架构、视口、手感和资源合法性；通过后再批量导入其余世界。直接先导入几十关会把问题推迟到后期，返工成本很高。

本次只做了只读调查和评估，没有修改现有关卡、源码或构建，也没有把 disassembly、ROM 或原始素材复制进 `Assets`。
